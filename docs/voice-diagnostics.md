# Диагностика голоса и безопасное обновление

## Результаты расследования (25 октября 2026)

База работы — актуальный на момент fetch `main` = `5b40ae0`.
Рабочий каталог был чистым, локальный `main` оставлен на прежнем коммите;
исправления выполнены в отдельной ветке от `origin/main`.
Файла AGENTS.md в checkout не найдено; применены инструкции пользователя.

PR #2 открыт, `mergeable: false`, head `2f4fc4a21fe79edd09d6bc057e99ef114ceae3f3`.
`git rev-parse 'origin/pr-2^{tree}' '2b4c16a^{tree}'` возвращает одно дерево
`bf40bab6a5d98a998395c70bac22755a1cfb9788`.
Коммит `2b4c16a` («Изм3003») уже является предком `main`: содержимое PR было
перенесено без слияния его истории. Поэтому PR #2 следует закрыть как
дублирующий после проверки нового PR. В ходе этой работы он не закрывался. `git merge-tree --write-tree` также подтвердил
конфликт public/app.js (без изменения checkout).

Подтверждённые дефекты и границы выводов:

* Конфигурацию перезаписывали inline-fetch, `/config.js` и дополнительный fetch
  из app.js. JSON возвращал только REST TURN, JS — только статический TURN и
  voiceLimit. При TURN_SECRET без TURN_URL JS мог стереть рабочий TURN; при
  статическом TURN JSON мог стереть его. Это объясняет зависимость от сети и
  порядка загрузки. Рабочая конфигурация конкретного VPS не исследовалась,
  поэтому причиной именно пользовательского сбоя это пока не объявляется.
* При accept до getUserMedia offer приходил во время подготовки микрофона.
  Воспроизведение на исходном `main` с задержкой микрофона 1500 мс показало
  **два живых PeerConnection у принимающего**: один `new`, второй `connected`.
  Тест корректно завершился ошибкой. В том прогоне аудио проходило, поэтому
  дублирование само по себе не доказывает причину каждого случая тишины.
* E2EE transforms устанавливались поздно и повторно. В процессе браузерной
  диагностики воспроизводились `Invalid state`, нулевая энергия аудио и
  искажённый сигнал при растущем RTP. Одной защиты от повторной установки
  оказалось недостаточно: receiver необходимо подготовить при addTrack,
  до remote SDP. После этого оба decrypt-потока работают и возвращают
  исходный тестовый тон. См. порядок установки в
  [WebRTC Encoded Transform](https://www.w3.org/TR/webrtc-encoded-transform/).
* `E2EE.supports` содержал функцию-конструктор вместо boolean: JSON.stringify
  пропускал `enabled` в invite. Теперь значение сериализуется корректно.
* Floor не участвовал в личных звонках. В комнате были отдельные дефекты:
  передача до snapshot, отсутствие фильтра комнаты/поколения вступления,
  отсутствие ответа проигравшему take, незавершённый PTT и несогласованное
  состояние дорожки при уходе владельца.

## Что изменено

Единственный загрузчик `/js/config.js` запрашивает `/config.json`; app.js ждёт
его promise, PeerConnection требует готовую конфигурацию. Ошибки HTTP/формата
видны на странице и блокируют запуск. Оба серверных config-endpoint используют
один builder, `Cache-Control: no-store`, сохраняют voiceLimit и TURN.
TURN_SECRET имеет приоритет над статическими credentials; TURN_URL при этом
задаёт URL REST TURN. Без TURN_URL сохраняются прежние три URL coroutine-chat.ru.
Не печатайте объект конфигурации: в нём есть временные TURN credentials.

Получатель отправляет accept после открытия микрофона и создания соединения;
повторное создание соединения защищено. ICE буферизуется до remoteDescription;
операции применения SDP/ICE упорядочены. Offer комнаты выбирается сравнением
clientId без зависимости от locale браузера. Streamless ontrack также поддержан.

E2EE transforms создаются синхронно с sender и парным receiver, до SDP.
Ожидание ключа закрыто для кадров; ключ передаётся worker через MessagePort
без замены transforms. Каждый endpoint получает ключ один раз. При завершении
звонка worker прекращается. Ошибки worker и таймаут завершают звонок;
автоматического перехода с запрошенного E2EE на обычный режим нет.
Обычные звонки продолжают использовать DTLS-SRTP. При интеграции с VPS сохранено его существующее E2EE комнаты: отдельные
название/секрет, производный непрозрачный ID, PBKDF2 и код сверки.
Workers комнаты и личного звонка изолированы. Opus TOC сохраняется и
аутентифицируется AES-GCM; непроверенный plaintext не принимается.

Вступление в комнату получает новый membershipId. До server snapshot микрофон
выключен. Сигналы другой комнаты/старого вступления отбрасываются клиентом и
сервером. Snapshot не может быть подменён peer-сообщением floorOwner.
При take один владелец; проигравший и чужой release получают актуальный snapshot.
Уход/закрытие WebSocket освобождают floor. Ping/pong удаляет зависший сокет
приблизительно за 15–30 секунд при настройках по умолчанию.

Mute — намерение пользователя, PTT — временное разрешение. Потеря floor отменяет
PTT. Освобождение floor автоматически снимает временную блокировку у всех
участников и возвращает их ручное состояние mute. Собственный release освобождает общий микрофон и сохраняет
ручной mute владельца: включённый микрофон продолжает работать, выключенный
остаётся выключенным. Удерживаемый PTT завершается с возвратом к ручному mute.
Взятие floor не отменяет осознанный mute. Вход заново сохраняет mute пользователя.
Неполученный snapshot через 5 секунд завершает вступление с явным сообщением.

Удалённые audio вызывают `play()` явно. При отказе появляется кнопка
«Включить звук собеседника» и стандартные controls. Успех/отказ доступны в
`audio.dataset.playback`; отказ выводит только имя ошибки.

## Автоматические проверки

```powershell
npm.cmd ci
npm.cmd test
```

`npm test` выполняет поведенческие Node-тесты и прежний smoke. Интеграционный
тест запускает настоящий HTTP/WS proxy, используя изолированный CHAT_DATA_DIR
и тестовый TCP sink. Проверяются единая конфигурация, конкурирующие take,
чужой release, старые membership/room, leave, disconnect, rejoin и потеря pong.
Unit-тесты проверяют готовность/ошибки config, ранний ICE, streamless track,
floor/Mute/PTT, playback retry, раннюю установку transforms, доставку ключей,
AES-GCM roundtrip и отказ на plaintext/повреждении/неверном ключе.

Дополнительная браузерная проверка требует установленный Playwright и Chromium:

```powershell
# В отдельной тестовой среде, если Playwright ещё не предоставлен:
npm.cmd install --no-save --package-lock=false playwright
npx.cmd playwright install chromium
npm.cmd run test:browser
```

Можно задать PLAYWRIGHT_MODULE (путь к предоставленному пакету) и
BROWSER_EXECUTABLE (путь к Edge/Chromium). В этой работе использовались
предоставленный Playwright 1.62.1 и установленный Edge headless, Node 24.16.0.
Открываются два изолированных контекста, авторизация подменена тестовым `/api/me`,
TCP framing моделируется fixture; production-аккаунты не создаются.
Синтетический WAV 440 Гц подаётся через fake microphone. Проверяются:

1. Комната, take/release, mute и PTT с реальными browser track.enabled.
2. Личный звонок без E2EE, E2EE по запросу только звонящего, E2EE по запросу
   только принимающего, ещё один обычный звонок.
3. Отключение владельца через UI, освобождение floor, повторный вход и голос.
4. Для каждого аудиосценария: один живой PC, connected, RTP в обе стороны,
   ненулевая энергия, FFT-пик около 441 Гц в декодированном remote stream,
   audio.paused=false, currentTime>0, readyState>=2.
5. Для E2EE — оба worker-счётчика encrypt/decrypt растут.

Флаг autoplay разрешён для теста. Политика реального браузера проверяется отдельно;
ветка отказа play() покрыта unit-тестом и браузерной имитацией NotAllowedError:
кнопка повтора видна и нажимается, после нажатия воспроизведение успешно. Артефакты синтетического теста остаются
в игнорируемой `.tmp/`; их нельзя включать в коммит.
`BASELINE_REF=5b40ae0` запускает ту же проверку на временной копии исходных
public/proxy, не меняя checkout. На исходной версии тест обнаруживает два PC.

Результат локальной проверки: 13 Node-тестов и smoke прошли; браузерная матрица
прошла с двусторонним сигналом. Это **не** проверка физических устройств,
настоящего TCP C++ процесса, VPS, NAT между компьютерами или TURN relay.
CMake в данной Windows-среде не найден, C++ тесты не запускались; C++ не менялся.
`npm ci` сообщил 6 существующих advisories; зависимости не обновлялись вне задачи.

## Проверка перед merge и обновлением VPS

1. На staging с HTTPS открыть приложение на двух компьютерах в разных сетях,
   обновить обе страницы. Выбрать реальные микрофоны и динамики, говорить по
   очереди. В комнате без floor оба слышны; после take слышен только владелец.
   Release автоматически возвращает звук тем, у кого микрофон был включён до
   захвата; ручной mute и PTT сохраняют описанные правила.
2. Повторить личные звонки с E2EE off, запросом E2EE от каждой стороны, завершить
   и вызвать заново. С E2EE обе стороны показывают «E2EE включено», речь понятна.
   Отказать микрофону/заблокировать autoplay: видна ошибка или кнопка включения.
3. До звонка открыть chrome://webrtc-internals либо edge://webrtc-internals.
   В DevTools дважды с интервалом 5 секунд выполнить
   `await WebRTCCall.diagnostics()`. Ожидать connected, live/enabled local audio,
   рост outbound/inbound packets и bytes, totalAudioEnergy при речи.
   `E2EE.diagnostics()` должен показывать рост encrypt/decrypt в E2EE-звонке.
   Рост RTP без слышимой речи не считать успехом. Выгрузки webrtc-internals
   содержат IP/SDP — не прикладывать их публично без удаления чувствительных данных.
4. На **staging** задать `ICE_TRANSPORT_POLICY=relay` при рабочих TURN settings,
   перезапустить proxy и обновить обе страницы. Повторить комнату, все звонки,
   повторный вызов и reconnect. В diagnostics candidateType должен быть `relay`,
   в selected candidate pair webrtc-internals также должен быть relay.
   Ошибки TURN — проверить TTL, время сервера, UDP/TCP/TLS доступность и coturn logs
   локально без публикации credentials. Вернуть `all` после теста.
5. Отключить сеть владельца на >30 секунд: floor освобождается, слушатель возвращается к своему
   ручному состоянию mute. Восстановить сеть, подключиться/вступить заново; прежний владелец не висит.

## Обновление и откат (только после отдельного разрешения)

1. До изменений записать текущий release SHA, фактический путь/имя сервиса,
   параметры запуска Node/nginx/coturn. Приватно сохранить конфигурацию и
   data/users.json, data/sessions.json; не помещать backup в Git или web-root.
2. Развернуть новый коммит отдельным release-каталогом, сохранить прежний каталог.
   Использовать прежние env и внешнюю директорию данных через CHAT_DATA_DIR;
   не брать `.env.example` как готовую production-конфигурацию.
   Выполнить `npm ci`, тесты и staging-проверки. Не трогать C++/coturn без причины.
3. В согласованное окно переключить proxy на новый release и перезапустить только
   его фактический сервис. Убедиться в HTTP/WS и `/config.json` без вывода тела
   конфигурации в общедоступные логи. Обновить **все** браузерные клиенты:
   протокол комнаты теперь требует membershipId. Старые открытые страницы
   несовместимы с новым вступлением; смешанные версии не являются тестом релиза.
4. Выполнить короткую проверку между двумя компьютерами из раздела выше.
   При регрессии переключить сервис на сохранённый предыдущий release SHA
   с прежними env/данными, перезапустить proxy и снова обновить страницы.
   Схема пользовательских данных не меняется, миграции/откат данных не требуются.
   Не применять reset --hard, force-push и очистку пользовательских файлов.

Первоначальный PR не менял production. Последующее развёртывание на VPS
разрешено пользователем отдельно; детали фиксируются в отчёте развёртывания.

## Интеграция с VPS

На VPS обнаружились незакоммиченные доработки E2EE комнат. Они сохранены
в отдельном приватном backup и перенесены в исходники этого PR. Код
шифрования Opus использует видимый TOC как authenticated additional data;
96-битный случайный nonce сохраняет независимость разных отправителей комнаты.
Тесты проверяют изменение TOC, разные секреты/ID и изоляцию room/call workers.
Браузерная матрица дополнена E2EE комнатой с проверкой спектра в обе стороны.

`VOICE_TEST_URL=https://coroutine-chats.com` позволяет выполнить браузерный
тест через настоящий HTTPS/WS/TCP сервера (тестовый /api/me подменяется только
в браузере; новые аккаунты не создаются). Временные probe-имена присутствуют
в списке онлайн до закрытия тестовых соединений. Без этой переменной
используются только локальные fixtures.

## Ограничение общего микрофона

Каждый захват общего микрофона даёт владельцу 60 секунд. Срок хранится на
сервере, участники видят оставшееся время. Через минуту сервер снимает
владение и рассылает новое состояние независимо от фоновой вкладки владельца.
Повторное take при занятом микрофоне не продлевает срок. Досрочный release,
уход и отключение отменяют прежний таймер; новый захват получает новую минуту.
Старый таймер не может освободить микрофон нового владельца.
Автоматическое освобождение, как и обычное, не меняет ручной mute владельца.

`VOICE_TEST_FLOOR_ONLY=1` запускает короткую браузерную проверку floor.
Дополнительно `VOICE_TEST_FLOOR_TIMER=1` ожидает настоящие 60 секунд и проверяет
серверное освобождение, видимый отсчёт и новую минуту при следующем захвате.
